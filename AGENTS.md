# Учебная CMS Кафедра

Работай по spec/ и decisions/. Роль агента — реализация, тестирование и технические рекомендации; окончательная приёмка принадлежит студенту.

Стек: Python, SQLite, собственный WSGI и рендерер, Pillow. Разрешена запись только в проекте cms/. Публичная отправка данных, push, установка системных программ и изменения внешних баз требуют отдельного поручения. Удаление чужих файлов, чтение и вывод настоящих .env, обход изоляции запрещены.

Реальные секреты хранятся только в исключённом .env. В экспериментах используются искусственные маркеры. Для проектных проверок использовать `python harness/commands.py content-audit` и `python harness/commands.py release-check`; общий прогон — `python tools/check.py`.

После изменения запусти нужные тесты, затем общий прогон перед релизом. Не подменяй тесты утверждениями о константах. Все права проверяются в сервисе. Пользовательские строки экранируются по умолчанию. SQL параметризован. Каждое изменение схемы имеет миграционный след.

Не выдумывай выполненные проверки, семестровые даты, решения пользователя, одобрение преподавателя, взаимный аудит и живую защиту. В журнале различай автоматическую техническую рекомендацию и личную приёмку студентом.

Перед использованием пакета проверь его доступность. В этой среде Flask и pytest не были установлены; выбран стандартный unittest. Для файлов и вывода используй UTF-8. Независимые агенты владеют разными файлами; контракт API согласуется явно.

Коммиты: `docs:`, `feat:`, `fix:`, `test:` с описанием смысла. Одна функциональная порция — одна ветка feature/. Не переписывай существующую историю и не отправляй изменения в удалённый репозиторий без поручения.

После аудита Windows: при ограничении доступа к файлам проверяй регистр без учёта case, запрошенный путь и конечную цель resolve. Служебное чтение материала всегда получает actor; внутренние методы репозитория не используются как публичный API.

После ошибки очистки временной базы: команды закрывают соединения в finally до удаления временного каталога. Перед релизом проверяется запуск в новой копии без data/; наличие старой базы не считается доказательством работоспособности миграций. Неуспешные протоколы сохраняются вместе с исправлениями.
