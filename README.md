# Учебный портал Кафедра

Собственная CMS и агентский харнесс для лабораторной и практической работ по дисциплине «Автоматизация проектирования интернет-приложений». Все данные демонстрационные. Версия 1.0.0. Код сгенерирован Codex 15.11.2026 по спецификациям, сохранённым до генерации в spec/.

## Запуск стенда одной командой

В PowerShell из каталога cms:

```powershell
.\run.ps1
```

Если политика PowerShell блокирует локальный сценарий, его можно запустить без постоянного изменения политики:

```powershell
powershell -ExecutionPolicy Bypass -File .\run.ps1
```

Скрипт использует доступный bundled Python Codex, .venv или Python из PATH. Если Pillow отсутствует, создаёт локальную .venv и устанавливает requirements.txt. Нужны Python 3.11+ и доступ к PyPI при первичной установке зависимости. На другой ОС: `python -m pip install -r requirements.txt`, затем `python app.py --demo`.

Открыть http://127.0.0.1:8080 . Вход /login: admin, editor или author; учебный пароль всех трёх пользователей `Demo-Only-2026!`. Он является публичной демонстрационной настройкой, а не секретом. Для другого начального пароля задайте переменную CMS_DEMO_PASSWORD до первого запуска. Повторный seed не меняет уже созданные учётные записи. Не размещать демонстрационный стенд в публичной сети.

Стандартный wsgiref предназначен для локального учебного стенда. Для внешнего развёртывания потребуются production WSGI-сервер, HTTPS, Secure cookie, индивидуальные пароли и отдельная проверка конфигурации. Внешний хостинг не настраивался.

## Проверка

```powershell
python tools/check.py
python harness/commands.py content-audit
python harness/commands.py release-check
```

Здесь `python` — тот же интерпретатор, которым запущен проект. В данной среде он найден сценарием run.ps1 в runtime Codex. Виртуальное окружение использует `.venv\Scripts\python.exe`. Проектный линтер проверяет синтаксис, пробелы, отступы, bare except, wildcard imports, eval/exec и shell=True; он не заменяет полный анализ потоков данных.

Команды не трогают рабочую базу: тесты и аудит создают временные базы. Полный протокол каждого вызова сохраняется в evidence/commands/. Записи failed сохранены намеренно как реальные результаты до исправления, итоговый релиз определяется последней записью release-check.

## Возможности

Четыре типа в schemas/: новость, курс, мероприятие, учебный ресурс. Поля title/body/slug/description/category/tags общие; дополнительные поля валидируются конфигурацией. Состояния draft, review, published, archived. Автор создаёт и редактирует свои черновики и отправляет на модерацию; редактор публикует и архивирует; администратор имеет полный доступ. Права действуют одинаково для всех четырёх типов; тесты проверяют операции в сервисе, а не только видимость кнопок.

SQLite: SQL-миграции в migrations/ и версионированный реестр JSON-схем в content_types/schema_history. Новому типу не нужна отдельная SQL-таблица: меняется конфигурация и реестр. Связи таксономии используют foreign keys. Каждая правка создаёт ревизию; восстановление возвращает материал в draft, чтобы не обходить модерацию.

Панель: поиск и фильтры, CRUD, переходы состояния, пакетные операции, ревизии и откат, загрузка изображений, аудит и статистика. Производные изображения формирует Pillow после декодирования содержимого. Публичная выдача содержит только published.

API: `/api/materials?page=1&page_size=10&type=news`, также фильтры category и tag. Максимальный page_size ограничен ядром. Публичная часть включает `/`, `/material/<slug>`, страницы типов/категорий, `/sitemap.xml`, `/robots.txt`. Две темы выбираются ссылкой в меню. Точный маршрут страницы материала и фильтры показаны в работающем меню и HTTP-тестах.

## Добавление типа без изменения ядра

Скопировать harness/experiment/spec.json в schemas/notice.json и перезапустить приложение. Новая схема регистрируется миграцией реестра, появляется в меню и форме администратора. Обязательные общие поля не дублируются в fields. Для защиты этот опыт удобнее проводить на копии проекта с отдельной базой. Автотест уже проверяет добавление типа и отказ несовместимой схемы.

## Структура и материалы сдачи

- core.py — репозитории, валидация, роли, сессии, ревизии, медиа и аналитика.
- web.py, templates/, static/ — собственный веб-слой и интерфейсы.
- spec/ — исходные постановки и шаблон.
- decisions/ — выбор агента, модели хранения и рендеринга.
- harness/ — правила, политика, команды, исследование постановок и управление контекстом.
- traces/ — санитизированные технические экспорты текущих сессий и аннотации.
- evidence/ — фактические результаты проверок, аудит и журнал ИИ.
- tests/ — проверки ядра, веб-сценариев и защитной оболочки.

Финальные отчёты включены в репозиторий: reports/Отчёт_ЛР.docx и reports/Отчёт_ПР.docx. Их копии также находятся в исходных папках ЛР/ и ПР/ дисциплины. Краткая подготовка к защите — DEFENSE.md.

## Развёртывание с нуля

Клонировать или распаковать проект в новый каталог без data/, uploads/, .venv/ и .env. Выполнить команду запуска; миграции и учебные данные создаются автоматически. Затем запустить release-check тем же интерпретатором. Проверка чистой миграции и HTTP-сценарии входят в комплект.

Фактически проверено: копия без data/ и .venv/ запущена командой `.\run.ps1 -Port 8082`; создалась база, главная, API и sitemap вернули HTTP 200, release-check завершился успешно. В этой среде Python и Pillow уже предоставлены runtime Codex; загрузка пакета из PyPI в данном опыте не требовалась. Протоколы — evidence/clean-deployment.json и clean-release.json.

Рабочая база находится в data/cms.sqlite3, изображения и производные — в data/media/. Для резервной копии остановить сервер и скопировать data/ целиком. Для учебного сброса безопаснее создать новую копию проекта без data/. Удаление рабочей базы не входит в команды харнесса.

Число записей журнала не раздувалось до формальных 25 вымышленными итерациями. Экспорты не содержат скрытого рассуждения, системных инструкций и идентификаторов аккаунта; пути профиля маскированы.
