# Команды проекта

`/content-audit` → `python harness/commands.py content-audit`. Вход: schemas/ и migrations/. Выход: проверка схем и миграция временной чистой базы; JSON-протокол в evidence/commands/. Ограничение: не меняет рабочую БД и не обращается в сеть.

`/release-check` → `python harness/commands.py release-check`. Вход: исходный код, спецификации, VERSION, README и CHANGELOG. Выход: проектный линтер, полный unittest-прогон, проверка файлов релиза и чистой миграции; полный stdout/stderr в JSON. Ограничение: локальная проверка без push, публикации и удаления рабочей базы.

Это воспроизводимые команды проекта, которые агент может вызвать из shell; установка глобальных slash-команд Codex не имитируется. Короткие имена используются в постановках как соглашение.

Экономия измеряется как число явных вызовов нижележащих проверок: content-audit объединяет чтение и валидацию четырёх схем и чистую миграцию в один вызов; release-check объединяет линтер, тесты, файлы релиза и миграцию. Экономия времени ручной работы не измерялась и не заявляется. Длительность реального выполнения сохраняется автоматически.
