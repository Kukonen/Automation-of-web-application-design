# Мини исследование постановок

Дата: 15.11.2026, один и тот же агент Codex, одна сессия независимого агента аудита. Задача: добавить тип объявлений с местом и датой.

Запрос A: «Добавь для нашей учебной CMS тип объявлений с местом и датой проведения». Агенту запрещены чтение файлов и инструменты. Результат без изменений сохранён в free.json: стандартная JSON Schema с properties и общими полями, несовместимая с контрактом ядра.

Запрос B: контекст об общих title/body/slug; точный контракт label/fields; location как обязательный text с max_length 200; event_date как обязательный date; запрет дополнительных ключей. Результат без изменений в spec.json.

Для A потребовалась дополнительная постановка с контрактом; B прошёл формальную проверку за один ответ, без ручных изменений JSON. Это показывает потерю интерфейсного требования в свободном запросе. Результаты проверки: evidence/experiment.json.

Ограничения: два ответа, один агент, последовательность A затем B, B видел предыдущий результат, файлы читать было запрещено. Это демонстрация влияния полноты входа, а не независимый статистический эксперимент и не оценка скорости моделей. Время генерации и число ручных правок после личной приёмки студентом не измерены.

Ролевая игра: роль заказчика выражена свободной фразой A; роль разработчика — переводом её в контракт B; роль агента — двумя JSON-ответами. Потерялись формат CMS и отсутствие общих полей; место и дата сохранились. Реальных однокурсников в эксперименте не было.
