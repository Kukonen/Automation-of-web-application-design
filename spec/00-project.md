# SPEC 00 Учебный портал Кафедра

Дата постановки: 15.11.2026. Автор реализации: Codex. Предметная область выбрана как рабочий вариант для учебного задания; согласование с преподавателем выполняет студент.

## Контекст
Собственная учебная CMS без готовых CMS и автоадминок. Общий репозиторий для лабораторной и практической работ. Стек: Python 3.11+, SQLite, WSGI из стандартной библиотеки, Pillow для производных изображений; unittest для проверок. Роутер, административный интерфейс и шаблонный слой принадлежат проекту.

## Требования
Четыре конфигурируемых типа: news (новость), course (курс), event (мероприятие), resource (учебный ресурс). Общие поля: title, slug, body, SEO description, category, tags. Дополнительные поля определяются JSON-схемой. Жизненный цикл: draft -> review -> published -> archived; возврат на доработку контролируется ролями. Автор редактирует свои черновики, редактор модерирует, администратор управляет всеми материалами и схемами.

SQLite с версионируемыми SQL-миграциями, внешними ключами, отдельными ревизиями и восстановлением. Аутентификация с хешами паролей и серверными сессиями. Все изменяющие операции защищены CSRF. Медиа ограничены изображениями, проверяется содержимое и создаются производные размеры.

Публичные страницы, рубрики, поиск, меню из схем; две темы, partial и наследование. HTML пользователя экранируется. REST API выдаёт только опубликованные материалы, поддерживает пагинацию и фильтр таксономии. SEO: slug, title, description, sitemap.xml, robots.txt. Аналитика просмотров, публикаций по дням и активности авторов.

## Приёмка
Запуск одной командой из README. Минимум 25 содержательных тестов ядра, 10 параметризованных проверок прав, 3 сквозных сценария. Проверка создания типа без изменения ядра, отката ревизии, XSS, CSRF, утечки черновиков через API, ограничений ролей и медиа. Линтер и тесты запускаются одной командой. Реальные результаты сохраняются в evidence/. Стенд локальный, внешняя публикация не требуется для учебного комплекта.

## Ограничения
Не выдумывать семестровую историю, решения студента, одобрение преподавателя или результаты живой защиты. Данные демонстрационные. Реальные пароли и ключи не помещать в Git. Инструментальные логи отличать от полного экспорта текущего чата, если он недоступен.
